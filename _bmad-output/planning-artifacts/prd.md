# PRD — MedLab: Менеджер медицинских анализов

**Версия:** 1.0
**Дата:** 2026-03-20
**Статус:** Draft

---

## 1. Обзор продукта

### 1.1 Цель
MedLab — персональное PWA-приложение для хранения, отслеживания и анализа медицинских показателей. Пользователи могут вести историю анализов для себя и членов семьи, получать автоматическую оценку отклонений от нормы и отслеживать динамику показателей.

### 1.2 Целевая аудитория
- Люди, следящие за своим здоровьем (25–60 лет)
- Родители, ведущие записи для детей
- Люди с хроническими заболеваниями, регулярно сдающие анализы
- Язык интерфейса: русский

### 1.3 Ключевые метрики успеха
- Время до первой записи анализа < 2 минут
- 0 случаев потери данных
- Корректная работа при 100+ одновременных пользователях
- Все критические уязвимости закрыты до продакшн-деплоя

## 2. Текущее состояние (As-Is)

| Компонент | Текущее решение | Проблема |
|-----------|----------------|----------|
| Хранилище данных | JSON-файлы на диске | Race conditions, нет транзакций, не масштабируется |
| Валидация | Только на клиенте | Bypass через прямые API-запросы |
| XSS-защита | Отсутствует | innerHTML без санитизации |
| Auth | JWT 30 дней, без revocation | Скомпрометированный токен действует 30 дней |
| Rate limiting | Только `/api/auth/*` | Остальные эндпоинты не защищены |
| Фронтенд | Монолит 1771 строк | Сложно поддерживать и тестировать |

## 3. Требования

### 3.1 Функциональные требования

#### FR-1: Аутентификация и профиль
- **FR-1.1** Регистрация по email + пароль (мин. 8 символов, буквы + цифры)
- **FR-1.2** Вход с JWT-токеном (7 дней, обновление при активности)
- **FR-1.3** Сброс пароля (через секретный вопрос или email)
- **FR-1.4** Редактирование профиля: имя, пол, дата рождения
- **FR-1.5** Удаление аккаунта со всеми данными (GDPR)
- **FR-1.6** Logout с немедленной инвалидацией токена

#### FR-2: Управление анализами
- **FR-2.1** Создание записи анализа: дата, лаборатория, врач, категория, параметры
- **FR-2.2** Редактирование и удаление записи
- **FR-2.3** Загрузка вложений (PDF, изображения, до 5 МБ)
- **FR-2.4** Парсинг PDF для автоматического извлечения показателей
- **FR-2.5** Пагинация: 20 записей на страницу
- **FR-2.6** Поиск по параметрам, лаборатории, дате, врачу
- **FR-2.7** Фильтрация по категории и дате

#### FR-3: Анализ показателей
- **FR-3.1** Автоматическое определение отклонений от нормы (87+ параметров)
- **FR-3.2** Учёт пола и возраста при оценке нормы
- **FR-3.3** График динамики по отдельному параметру
- **FR-3.4** Индикаторы тренда (↑↓ с % изменения)
- **FR-3.5** Сводная статистика на дашборде
- **FR-3.6** Уведомление при критическом отклонении показателя от нормы

#### FR-4: Семейные профили
- **FR-4.1** Добавление/редактирование/удаление членов семьи
- **FR-4.2** Отдельная история анализов на каждого члена семьи
- **FR-4.3** Учёт пола/возраста каждого члена при оценке норм

#### FR-5: Данные и экспорт
- **FR-5.1** Экспорт всех данных в JSON
- **FR-5.2** Импорт с дедупликацией
- **FR-5.3** Экспорт истории параметра в CSV

#### FR-6: PWA
- **FR-6.1** Оффлайн-доступ к ранее загруженным данным
- **FR-6.2** Установка как нативное приложение (iOS/Android/Desktop)
- **FR-6.3** Push-уведомление о плановом визите к врачу

---

### 3.2 Нефункциональные требования

#### NFR-1: Безопасность
- **NFR-1.1** Серверная валидация всех входных данных (zod-схемы)
- **NFR-1.2** Санитизация вывода — никакого innerHTML с пользовательскими данными
- **NFR-1.3** JWT revocation при logout (blacklist в БД)
- **NFR-1.4** Rate limiting на все API-эндпоинты (100 req/мин на пользователя)
- **NFR-1.5** CSP без `unsafe-inline`
- **NFR-1.6** HTTPS обязателен в продакшне
- **NFR-1.7** Пароли: bcrypt, 12 rounds, мин. 8 символов

#### NFR-2: Производительность
- **NFR-2.1** Первая загрузка страницы < 2 секунды
- **NFR-2.2** API-ответы < 200 мс (p95)
- **NFR-2.3** Поддержка 100+ одновременных пользователей без деградации
- **NFR-2.4** Пагинация — не загружать все данные сразу

#### NFR-3: Надёжность
- **NFR-3.1** SQLite с транзакциями — нет race conditions
- **NFR-3.2** Автоматические бэкапы БД (ежедневно)
- **NFR-3.3** Graceful error handling на всех эндпоинтах

#### NFR-4: Поддерживаемость
- **NFR-4.1** Фронтенд разбит на ES-модули по ответственности
- **NFR-4.2** API покрыт e2e-тестами на все happy path и основные edge cases
- **NFR-4.3** Логирование запросов и ошибок (morgan + winston или аналог)

## 4. Что НЕ входит в скоуп

- Интеграция с медицинскими системами (FHIR, HL7)
- Телемедицина / чат с врачом
- Распознавание изображений анализов (OCR)
- Мобильное нативное приложение (React Native / Flutter)
- Мультиязычность (только русский)
- Синхронизация между устройствами через облако (только self-hosted)

---

## 5. Зависимости и ограничения

- **Runtime:** Node.js 20+
- **БД:** SQLite через `better-sqlite3` (уже в зависимостях)
- **Деплой:** Self-hosted, один сервер
- **Хранилище вложений:** Файловая система (до пересмотра архитектуры)
- **Email:** Опционально (для password reset) — SMTP конфиг через `.env`

## 6. Спринты и приоритеты

> Цель: устранить все критические уязвимости, перейти на БД
